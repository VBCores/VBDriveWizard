# Общее описание

Приложение служит для удоного взаимодействия пользователя с элеткроприводами VBDrive (https://github.com/VBCores/VBDrive). Сценарии использования приложения: первичная настройка приводов, проверка работоспособности всех узлов приводов. Приложение должно быть совместимо с ОС Ubuntu 24.04. Должно быть написано на C++, используя Qt 6.4. Основа главного окна уже создана (файл mainwindow.ui). При написании кода можно ориентироваться на приложение RWIP_GUI (/media/yoggi/Data/Work/LabWorks/ReactionWheel/RWIP_GUI/RWIP_GUI) - в нем хорошо реализована работа с отрисовкой графиков и визуальная тема элементов интерфейса. Код должен быть идиоматическим и эффективным с точки зрения времени выполнения. В проекте уже реализован макет mainwindow.ui, при разработке нужно опираться именно на него.

# Описание функционала

## Подключение
- программа должна поддерживать подключение по CAN и по Serial. Протокол обмена описан в репозитории к приводу. Выбор интерфейса подключения осуществляется путем выбора между SerialRadioBtn и CanRadioBtn. 
- В списке SerialCombo должны располагаться текущие Serial-устройства, подключенные к компьютеру
- В списке CanCombo должны располагаться текущие CAN-устройства, подключенные к компьютеру 
- По нажатию на кнопку SerialConnectBtn осуществляется подключение к соответствующему устройству по Serial-интерфейсу. При подключении должен происходить запрос регистра vbdrive_model. Если есть ответ, то считать устройство подключившимся. Иначе выдать окно с ошибкой подключения.
- Кнопка SerialRefreshBtn осуществляет обновление Serial-устройств в списке SerialCombo
- По нажатию на кнопку CanConnectBtn осуществляется подключение по CAN. На 5 секунд происходит запуск отдельного потока, который слушает heartbits от всех Cyphal-устройств, подключенных к ПК. Если приходит heartbit, то должен производиться опрос модели привода и NODE ID. Соответствующая информация попадает в список DeviceList.
- Кнопка CanRefreshBtn осуществляет обновление Serial-устройств в списке SerialCombo

- Когда соединение по Serial активно все элементы управления внутри ConnectionGroupBox должны быть enabled(false), кроме кнопки SerialConnectBtn. Она должна быть enabled(true), а текст должен быть Disconnect. При нажатии на Disconnect, она опять переименуется в Connect, а все элементы управления в ConnectionGroupBox становятся активны.
- Когда соединение по CAN активно все элементы управления внутри ConnectionGroupBox должны быть enabled(false), кроме кнопки CanConnectBtn. Она должна быть enabled(true), а текст должен быть Disconnect. При нажатии на Disconnect, она опять переименуется в Connect, а все элементы управления в ConnectionGroupBox становятся активны.

- когда программа не подключена к приводу, то все элементы управления программы должны быть enabled(false), кроме следующих: кнопки SavePltCsvBtn,SavePltPngBtn, выпадающие списки SignalComboBox, UnitsComboBox, LanguageComboBox. При успешном подключении все элементы управления становятся enabled(true), если на это не дается дополнительных условий.
- при подклювению по CAN нельзя менять параметры в DataBaudLineEdit и NomBaudLineEdit - они должны быть enabled(false).

- при подключении явно задается регистр is_on:1. При отключении is_on:0 для всех подключенных приводов.

## DEVICES

В списке DeviceList должны отображаться все приводы, которые в настоящией момент подключены к ПК. У списка должно быть две колонки: Модель привода и Node ID. Элементы внутри DevicesGroupBox должны быть enabled(true) только когда активно подключение по CAN. При нажатии на item внутри DeviceList начинается работа с конкретным выбранным приводом: все команды задаются только ему и чтение данных происходит только с этого привода. Команды связанные с вращением (например, синус, меандр и тд) не должны сбрасываться при выборе другого привода - поток отвечающий за формирование этих команд должен продолжать работать и привод должен вращаться по формируемой траектории.
- При формировании списка активный тот item внутри списка, который был обнаружен первым.
- У пользователя должна бытть возможность упорядочивать элементы внутри списка устройств по моделям или по ID.
- Если выбирается новый item, то должно появится уведомление о сохранениии измененых параметров регистров с выбором Да, Нет, Отмена.

## CONFIGURATION

- В ConfigGroupBox отображаются все конфигурационные регистры привода. Вкладка Basic - базовые параметры, связанные с ограничениями на работу привода и положительное направление вращения. Вкладка CAN - параметры работы с шиной CAN для привода. Вкладка Advanced - рашсиренные параметры, куда обчному пользователю обычно не стоит лезть. Вкладка System - калибровка датчика, загрузка и сохранения файлов конфигурации регистров, обновление прошивки привода.

- Внутри системы должен храниться список с заданными параметрами DeviceParamList, которые были загружены с привода в момент первого подключения к нему. Загрузка параметров происходит при выборе привода. Потом при установке нового параметра, когда новый параметр начинает отличаться от старого, должен высветиться QLabel с текстом Restore. После нажатия на Restore параметр снова возвращается к тому, который был в списке DeviceParamList, а Qlabel Restore становится невидимым. 

- Все QLabel с текстом Restore, которые имеют имена по умолчанию заданные Qt Creator должны быть переименованы в осмысленные названия по аналогии с располагающимися на вкладке Basic. Это же относится и к другим элементам управления в группе Configuration.

- при нажатии на кнопку ReadRegBtn проиходит чтение всех параметров привода, которые перечислены в группе CONFIGURATION. При этом DeviceParamList не обновляется.
- при нажатии на кнопку WriteRegBtn происходит запись всех параметров, которые были отредактированы пользователем. Видимые лейблы Restore не исчезают. У пользователя должна быть возможность несмотря ни на что вернуть старые параметры в случае возникновения проблемы.
- При нажатии на кнопку Set Origin происходит установка текущего положения привода в качестве нулевого: используется чтение текущих показаний датчика и запись в регистр ang_off.

### Вкладка Basic
- во вкладке Basic параметры заданы в виде чекбоксов. Если чекбокс не выбран, то это означает отсутствие ограничений и в соответствующий регистр записывается NaN. 

### Вкладка CAN
- как уже говорилось выше, параметры отвечающие за Baudrate, активны только при подключении по Serial.

### Вкладка Advanced
- В EncoderTypeComboBox сейчас три параметра, но привод пока что поддерживает только параметры rotor и shaft. Сделай external невидимым так, чтобы при появлении этой функции в приводе, можно было легко отобразить этот параметр.

### Вкладка System
- по нажатию на кнопку CalibrateBtn происходит калибровка датчика командой CALIBRATE. В будущем в протокол обмена привода будут внесены изменения: во время калибровки отправлять CALIBRATE OK, затем процент завершения калибровки, а под конец CALIBRATE FINISH. Пока этого нет, просто нужно отправить команду CALIBRATE и ничего не делать. Кнопка  CalibrateBtn доступна только при подключении по Serial, так как в CAN эта команда не реализована на стороне привода.

- в папке registers должны храниться yaml-файлы со значениями регистров. Файлы vbdrive_m4310r36.yaml и vbdrive_m4310r10.yaml уже должны существовать по умолчанию. Тебе необходимо создать эти файлы и заполнить их значениями по умолчанию из репозитория привода. Пока что эти файлы должны быть одинаковыми по содержанию.

- по нажатию на кнопку SaveRegBtn открывается окно для сохранения нового yaml-файла с текущим состоянием всех параметров привода
- по нажатию на кнопку LoadRegBtn открывается окно для выбора существующего yaml-файла с параметрами. При загрузке файла обновляются все поля регистров, но список DeviceParamList не обновляется, и соответственно лейблы Restore должны вести себя, как им положено.
- по нажатию на кнопку RestoreRegBtn открывается окно QDialog (его нужно содать) c QComboBox, где можно выбрать модель привода (их пока только две: M4310R10, M4310R36). Когда пользователь выбирает модель и нажимает ОК, то происходит загрузка параметров из файла vbdrive_m4310r36.yaml или vbdrive_m4310r10.yaml в зависимости от выбора пользователя.

- возможно загружать прошивку может работать только при соединении по Serial
- загрузка прошивок должна происходить посредством OpenOCD. 
- в CurFirmwareRevLabel отображается текущая версия прошивки (её можно прочитать из регистра).
- при выборе ChooseFirmwareFileRadioButton кнопка OpenHexPushButton становится кликабельной. 
- при нажатии на OpenHexPushButton открывается окно выбора hex-файла с прошивкой
- при выборе DownloadFirmwareRadioButton должна происходить загрузка последней версии прошивки из релизов репозитория VBDrive.
- поведение кнопки FlashPushButton: если выбрано ChooseFirmwareFileRadioButton, то происходит заливка выбранного пользователем hex-файла; если выбрано DownloadFirmwareRadioButton, то происходит загрузка последнего релиза из репозитория VBDrive, а затем заливка скачанного файла на микроконтроллер привода.
- все прошивки хранятся в папке firmwares
- во время загрузки прошивки FlashProgressBar отображает прогресс загрузки, если это возможно в OpenOCD.


## REALTIME DATA

- UnitsComboBox служит для выбора единиц измерения: градусами и радианами. Выбор единиц измерения влияет на всю программу при отображении углов и установке параметров. По умолчанию в привод работает с радианами. Программа сама должна осуществлять перевод из градусов в радианы при установке параметров, чтобы недопустить неправильную работу привода.
- LanguageComboBox позволяет переключать язык программы между Английским, Русским и Китайским. Программа должна поддерживать эти языки, и весь текст в программе должен иметь перевод на выбранный язык.
- Вместо PlotLabel должен отображаться график, показывающий информацию в реальном времени. Он должен быть реализован по аналогии с RWIP_GUI. 
- В SignalComboBox происходит выбор отображаемого на графике сигнала. Когда происходит выбор другого сигнала, то рисоваться должен именно этот сигнал - не должно быть никаких фоновых чтений и отрисовок, чтобы не тормозить систему.
- Кнопки Pause, Save as CSV, Save as PNG работают аналогично таким же кнопкам в RWIP_GUI. Сохраняется именно тот сигнал, который сейчас выбран.
- Если у сигнала есть задающее значение, то оно должно также отображаться.

- При нажатии на кнопку Preferences открывается окно в параметрами по аналогии с RWIP_GUI. В окне должны быть только параметры, касающиеся программы: внешний вид, размеры шрифтов, etc. Языка там быть не должно, так как он уже есть в mainwindow.

## CONTROL

В этой группе происходит установка желаемых состояний привода. В приводе реализовано два протокола Servo и MIT. Servo лучше подходит новичкам, MIT - для реализации сложного управления роботами.

Все элементы в группе ControlGroupBox должны иметь осмысленные названия.

### Вкладка SERVO

 - В группе Control Type выбирается тип задающего сигнала
 - В группе Transient Form выбирается тип переходного процесса. За них отвечают регистры servo_tr_form и servo_tr_vel. При нажатии на кнопку Set происходит запись в эти регистры выбранных параметров.
 - в группе Feedback Gains происходит выбор коэффициентов регулятора для выбранного типа управления в группе Control Type. Поведение: если выбрано Position, то все элементы Enabled; если выбрано Velocity, то доступны только Kp и Ki; елси выбрано Torque, то ничего не доступно, включая кнопку Set. По нажатию на кнопку Set происходит запись коэффициентов регулятора в соответствующие регистры.
 - в RefTrajectoryTabWidget располагаются вкладки для разных типов траектории. Если выбрана вкладка User, то пользователь может задавать произвольное заданное значение. Если выбрана вкладка Sin, то пользователь задает параметры синусоидального задающего сигнала. По нажатию на кнопку Start в отдельном потоке должен производиться расчет траектории и её отправка в привод. Для Meander и Triangle аналогичная ситуация. Замечание: если пользователь допустим запустил синусоидальную траекторию, а потом запустил, например, треугольную, то программа должна начать формировать новую выбранную желаемую траекторию. 
 - Если соединение идет по CAN, то при смене привода траеткория не должна останавливаться. Это нужно для проверки работы все приводов. 
 - во время отработки задающих сигналов у пользователя должна быть возможность смены типа управления, формы переходного процесса и коэффициентов регулятора.
 - Частота формирования траектории 100 Гц.

### MIT

- В группе Trajectory пользователь может выбрать форму задающей траектории
- StepTargetsGroupBox становится visible только когда выбрана траектория Step
- TrajectoryTargetsGroupBox становится visible только когда выбраны остальные траектории
- в StepTargetsGroupBox идет один в один заполнение полями сообщения mit_cmd для Serial или voltbro.foc.MITCommand.1.0 для Cyphal.
- В Trajectory Targets выбираются амплитуда и частота сигнала. Радиокнопки position, velocity и torque показывают тип задающего сигнала, т.е. если выбран Torque при синусоидальном сигнале, то значит синусоидальный сигнал формируется только для Torque. Также в этой группе задаются коэффициенты Kp и Kd (position gain и velocity gain соответственно).
- Если выбрана радиокнопка Position, то можно вбырать чекбокс +derivative. В этом случае вместе с положением также задается скорость, которая является производной от траектории заданного положения.
- При нажатии на кнопку Start происходит отправка выбранного сигнала. Здающий сигнал, аналогично режиму Servo, должен задавать в отдельном потоке и не прекращаться даже при выборе другого привода. 
- Частота формирования траектории 1 кГц.
